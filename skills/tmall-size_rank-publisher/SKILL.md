# Tmall Size Rank Publisher（淘宝商品编辑-尺码排序提交）

## 概览

验证淘宝卖家中心登录状态后，直接通过URL进入商品编辑页面，自动完成身高/尺码模块的从小到大排序，然后提交保存。过程中弹窗自动识别并按规则处理，出错时自动学习重试。

## 前置条件

| 条件 | 说明 |
|------|------|
| Chrome CDP 9222 | Chrome 浏览器以 `--remote-debugging-port=9222` 启动 |
| 已登录 | 已登录淘宝/天猫卖家后台（复用浏览器登录态） |
| 商品存在 | 目标商品ID在卖家中心-出售中商品中存在 |

## 参数

| 参数 | 必填 | 说明 |
|------|------|------|
| `item_id` | 是 | 商品ID，如 1087413592768 |
| `cdp_url` | 否 | CDP 浏览器地址，默认 `http://127.0.0.1:9222` |

## 执行流程

### Step 1 验证登录状态
打开 `https://myseller.taobao.com/home.htm/SellManage`，确认已登录状态。如果未登录，交给用户手动登录。

### Step 2 直接进入商品编辑页面
通过URL直接打开商品编辑页面：
```
https://sell.publish.tmall.com/tmall/publish.htm?id=<商品ID>
```

等待页面完全加载，确认销售属性区域可见。

### Step 3 处理"商品属性信息更新确定"弹窗
打开页面后可能弹出"商品属性信息更新确定"弹窗：
- **弹窗内容**：提示商品属性信息已更新，询问是否采纳
- **操作**：点击 **"取消"** 按钮（不采纳更新，保留原有属性）

### Step 4 尺码排序（含确认排序）
调用 tmall-height-sorter 的逻辑，对身高模块进行从小到大排序：
1. 点击身高模块的"排序"按钮
2. 通过 React API 设置正确顺序
3. **点击"确认排序"按钮**（必须点击，否则排序不生效）

### Step 4.5 设置店铺智能优惠为"否"
店铺智能优惠是必填项，默认未选择会导致提交失败。
- **选项位置**：销售信息模块下，"店铺智能优惠"区域
- **组件类型**：天猫自定义 `sell-radio` 组件（不是标准 Next UI radio）
- **选项含义**：
  - 抢占流量 = 是
  - **放弃机会 = 否**（自动选择此项）
- **操作**：找到文本为"放弃机会"的 `span.item-label`，点击其最近的 `label` 元素
- **验证**：点击后检查 `.sell-radio` 容器内是否有 `.checked` 元素，确认选中成功

### Step 5 提交商品
点击页面底部浮动栏的"提交"按钮，保存商品修改。

**提交按钮位置**：
- 选择器：`.sell-float-bottom button.next-btn-primary`
- 位置：页面底部固定浮动栏
- 文本："提交"

### Step 6 处理"图文详情编辑器升级提示"弹窗
提交后会弹出"图文详情编辑器升级提示"弹窗：
- **弹窗内容**：提示图文详情编辑器将升级，历史内容将优先取用无线端数据
- **操作**：点击 **"确认提交"** 按钮（继续提交，不返回修改）

### Step 7 验证结果
确认提交成功。**验证方式（v4 优化版）**：
1. **循环等待与检测**：提交后开始循环，最多等待 15 秒，每 1-1.5 秒检测一次：
   - **检测1 - 成功页**：通过 `GET http://127.0.0.1:9222/json` 检查标签页列表，是否有 `success.htm` + `isSuccess=true` 的页面
   - **检测2 - 校验错误**：直接读取页面左侧错误面板，是否有红色错误项
   - **检测3 - 弹窗**：是否有"确认提交"弹窗，有就点击
2. **一旦检测到成功或错误，立刻退出循环**，不傻等满 15 秒
3. **错误检测方法**：优先定位页面左侧的错误面板（红色叉号图标 + 错误文字），比全局遍历更快更准

**成功标志**：
- 标签页列表中存在 URL 包含 `success.htm` 且 `isSuccess=true` 的标签页

**常见失败原因库（实际运行积累）**：
- ✅ 已自动处理：店铺智能优惠 - 必填项未填（自动选"放弃机会"）
- ⏭️ 记录为"跳过"：基础信息模块必填项缺失
  - 必填项适用人群不能为空
  - 必填项内里材质不能为空
  - 必填项鞋底厚度不能为空
  - 必填项鞋跟高度不能为空
  - 必填项鞋跟款式不能为空
  - 必填项适用场景不能为空
  - 必填项针织面料不能为空
  - 必填项款式细节不能为空
  - 必填项蓬松度(FP)不能为空
  - 必填项肩带设计类型不能为空
- ⏭️ 记录为"跳过"：销售信息模块必填项缺失
  - 销售规格必填项未填
- ❌ 记录为"失败"：未检测到成功页面跳转（可能是弹窗延迟、滑块验证等）

### Step 8 清理标签页
处理完后关闭所有天猫发布相关的标签页，避免多标签页冲突。

### 错误处理与学习
如果提交后出现错误（如属性缺失、校验失败等）：
1. 记录错误信息和页面状态
2. 分析错误原因
3. 学习新的处理步骤
4. 重试整个流程
5. 最多重试 3 次

## 弹窗捕捉模式

| 弹窗类型 | 出现时机 | 识别方式 | 操作 |
|----------|----------|----------|------|
| 商品属性信息更新确定 | 打开编辑页面时 | 弹窗文本包含"商品属性信息更新" | 点击"取消" |
| 图文详情编辑器升级提示 | 点击提交后 | 弹窗文本包含"图文详情编辑器升级" | 点击"确认提交" |
| 其他确认提示 | 任意时机 | 弹窗文本包含"确定"/"知道了" | 点击"确定" |

**弹窗识别方式**：
- 遍历所有可见的弹窗元素（`.next-dialog`、`.next-modal` 等）
- 检查弹窗文本内容，匹配弹窗类型
- 找到对应按钮并点击

## 批量处理模式

当用户提供Excel文件（包含多个商品ID）时，使用批量处理模式：

### 输入格式
- Excel文件，第一列为商品ID
- 无表头，第一行开始就是数据
- 支持数万行规模

### 执行命令
```bash
python scripts/batch_publisher.py \
  --excel <Excel文件路径> \
  --cdp-url http://127.0.0.1:9222 \
  --wait-ms 2000 \
  --start-row 1 \
  --end-row <可选，结束行号>
```

### 输出格式
- 结果Excel文件包含三列：
  - **A列（商品ID）**：商品ID
  - **B列（执行结果）**：成功 / 跳过 / 失败
  - **C列（错误原因）**：失败或跳过时记录原因
- 每处理5个自动保存一次，防止意外丢失进度

**状态说明**：
- **成功**：尺码排序完成并提交成功
- **跳过**：商品有其他必填项缺失（除店铺智能优惠外），无法提交，已自动设置店铺智能优惠为否，但仍有其他必填项未填
- **失败**：其他异常错误（如页面打不开、提交按钮未找到等）

### 批量处理流程
1. 验证登录状态
2. 读取Excel文件，获取所有商品ID
3. 逐个处理每个商品ID：
   - 直接通过URL打开商品编辑页面
   - 处理"商品属性信息更新"弹窗（点击取消）
   - 执行身高排序（含确认排序）
   - 点击提交按钮
   - 处理"图文详情编辑器升级"弹窗（点击确认提交）
   - 验证提交结果
   - 关闭所有天猫标签页
4. 将结果写回Excel对应行
5. 每5个自动保存进度

### 断点续传
- 自动加载已有结果文件，**跳过已成功的商品**，只重新处理失败的
- 每处理 5 个商品自动保存一次，防止意外丢失进度
- 重新运行脚本即可继续处理，无需手动指定起始行

## 技术要点

- 复用 `tmall-height-sorter` 的身高排序逻辑
- 复用 `crawshrimp-skill` 的 CDP 浏览器操作层
- 弹窗自动识别和分类处理（属性更新→取消，详情升级→确认提交）
- 批量处理自动写回Excel，支持断点续传（自动跳过已成功的）
- 每个商品处理完后关闭所有天猫标签页，避免多标签页冲突
- **验证逻辑（v4）**：提交后循环检测（成功页/错误面板/弹窗），最多15秒，检测到结果立刻退出
- **错误检测**：优先读取左侧错误面板（红色叉号），比全局遍历更快更准
- **随机等待**：商品之间随机等待 1-5 秒，减少滑块验证触发概率
- **滑块验证检测**：检测到滑块时暂停，提示用户手动完成
- **店铺智能优惠**：天猫自定义 `sell-radio` 组件，找到"放弃机会"文本后点击父级 label

## 实际运行数据参考（1040个商品批量处理）

| 状态 | 数量 | 占比 |
|------|------|------|
| 成功 | ~626 | ~60% |
| 跳过（必填项缺失） | ~240+ | ~23% |
| 失败（未检测到成功页） | ~170+ | ~17% |

**说明**：
- 成功率约 60-70%，失败主要是因为商品本身有其他必填项缺失
- 失败的商品可以重新运行脚本重试，部分是因为弹窗延迟导致
